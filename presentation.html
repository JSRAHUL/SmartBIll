CONTEXT & MOTIVATION

Official Problem Statement & Industry Need

Bridging the gap between a basic CLI script and an enterprise-grade retail POS system
OFFICIAL UNIVERSITY PROBLEM STATEMENT

“Design and develop a Bill Generator application using Python that generates a customer bill for purchased products. The program should allow users to enter product details, quantity, and price, calculate the total amount, apply GST (if applicable), and display a formatted bill.”

Engineering Scope Extension:

Rather than an ephemeral terminal script, SmartBill evolves into a complete, full-stack web application with SQLite database persistence, interactive cart manipulation, real-time stock guards, and executive analytics.

Pain Points in Manual Retail Billing
  • • Manual arithmetic errors causing revenue leakage and disputes.
  • • Disconnection between checkout counters and warehouse inventory.
  • • Complex multi-slab GST tax rates (0%, 5%, 12%, 18%, 28%) handled with guesswork.
  • • Lack of customer purchase histories and profit margin transparency.
The SmartBill Solution Paradigm
  • ✔ Sub-second live cart recalculations with client-side validation.
  • ✔ Automated stock guards physically preventing overselling.
  • ✔ Per-line CGST (50%) & SGST (50%) transparent statutory breakdowns.
  • ✔ Executive Dashboard with live turnover, profit, and trend charts.

DATA ARCHITECTURE

Normalized Relational Database Schema

Structured into five normalized tables with cascading foreign keys and snapshot pricing
TABLE: products Catalogue & Stock
id (PK), name, category, cost_price, price, stock, gst_rate, discount_percent
TABLE: customers Profiles & Loyalty
id (PK), name, phone (UNIQUE), email, address, created_at
TABLE: bills Master Invoices
id (PK), bill_number (UNIQUE), customer_name, customer_phone, subtotal, discount_amount, gst_amount, grand_total, payment_method, amount_paid, change_due, created_at
TABLE: bill_items Granular Order Lines
id (PK), bill_id (FK -> bills.id), product_id (FK -> products.id), product_name, quantity, unit_price, gst_rate, line_total
TABLE: users RBAC Authentication
id (PK), username (UNIQUE), password, role ('admin' | 'cashier'), created_at
Integrity Highlights:
• Foreign key cascades preserve referential honesty.
• Snapshot pricing logs exact sale rate regardless of future catalogue price edits.
• Unique phone indexing eliminates customer duplication.

CORE ALGORITHMS

Financial Computation Engine & Formulations

Mathematical accuracy engineered to meet Indian taxation standards and retail rules
1. Dual-Tier Discount Algorithm
# Level 1: Item Promotional Cut item_discount = unit_price * (discount_pct / 100.0) effective_price = unit_price - item_discount # Level 2: Cart-Wide Discount (Conditional) if subtotal >= min_order_threshold: if discount_type == 'percentage': cart_discount = subtotal * (cart_pct / 100.0) else: cart_discount = min(flat_discount, subtotal)
2. Multi-Slab GST Division
# Slabs: 0%, 5%, 12%, 18%, 28% line_taxable = effective_price * quantity item_gst = line_taxable * (gst_rate / 100.0) # Statutory Split between Central & State cgst_amount = item_gst / 2.0 # 50% CGST sgst_amount = item_gst / 2.0 # 50% SGST total_line = line_taxable + item_gst
3. Net Invoice Formulation
subtotal = sum(effective_price * qty) total_gst = sum(item_gst) # Grand Total Equation grand_total = (subtotal - cart_discount) + total_gst grand_total = round(grand_total, 2)
4. Change Tender Due Calculation
if payment_method == 'Cash': if amount_paid < grand_total: raise ValidationError("Amount paid is less than total!") change_due = round(amount_paid - grand_total, 2) else: amount_paid = grand_total change_due = 0.00

POINT OF SALE WORKFLOW

Frictionless 4-Step POS Billing Sequence

Optimized for keyboard speed, minimal counter latency, and instant thermal printing
STEP 1
Product & Customer Entry

Live dropdown search by product name or SKU barcode. Selecting an item auto-populates unit price, stock on hand, and applicable GST slab.

STEP 2
Live Cart Validation

Client-side DOM updates calculate line subtotals dynamically. Cart prevents adding quantities higher than available inventory count.

STEP 3
Tender & Change Calculation

Supports Cash, Card, and UPI. Entering cash tendered automatically displays exact change due, eliminating mental calculation errors.

STEP 4
Atomic Commit & Receipt

In a single database transaction, the bill is saved, warehouse stock decremented, and an 80mm thermal receipt modal is rendered.

RECEIPT DESIGN HIGHLIGHTS
• 80mm Thermal Friendly: Monospaced itemization with clean dashed dividing lines.
• Statutory Transparency: Displays line item rates, discounts saved, and CGST/SGST breakdown.
• One-Click Print: Direct browser integration with window.print() targeting print CSS.

CASHIER ROLE
Point of Sale
  • ✔ Fast POS checkout screen with instant receipt printing
  • ✔ Read-only price and stock check for customer queries
  • ✔ Customer directory lookups to attach orders
